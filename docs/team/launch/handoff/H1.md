## Answers to the lead's questions

- **Event offer plus mutation:** fine, and intended. The hook runs before `MutationCatalog.Roll`, so a Pumpkin offer can be Golden and so on at the normal mutation odds. Mutation odds don't depend on species, and this doesn't change the number of rng draws in the mutation roll.
- **`chance` on an event offer:** Pumpkin is in `Catalog.Order` with weight 0, so `ChickenLuck.Odds` fills `odds.Pumpkin = 0`. It is never nil, so nothing errors. No client code reads `offer.chance` today (checked: only crate code reads `.chance`), so 0 is harmless. To keep it honest I ask for one line below that sets it to `Config.Event.OfferChance`.
- **Price and level for a weight-0 species:** both work. `Rules.RecruitPrice("Pumpkin", L)` equals Knight's (`Catalog.Pumpkin.price` is Knight's), and `Rules.RecruitLevel` only counts owned copies of the species. Covered by a test: level 1 at $Knight, then level 2 after owning a level-3 Pumpkin.
- **Exclusion from normal odds:** `ChickenLuck` only puts a species into a band when `weight > 0 and not crateExclusive`. Every other species gets odds 0, and `Rules.Draw` can't return a zero-odds id (its cumulative sum doesn't grow). `ShopCatalog`'s Luck-pass list needs `weight > 0`. The `AppController` Odds page and the ShopBrowser pass table skip zero chances. Normal odds for every other species are unchanged at every Luck level. Inserting a zero-odds id mid-Order doesn't move any other species' cumulative interval.
- **`Catalog.Order` users:** Index count becomes N+1 for everyone (new cards render as silhouettes). PlayerSession load/discovery accept it as a known species. The Admin grant list and the debug panel gain one entry. DebugService `FillMixed` picks by Order index, which only changes debug test flocks. `RollStation.cosmeticSpecies` is set but never read. Select Best, fusion (Giant band by rarity Epic), kill coins (`economyBase`) and refunds all follow the Knight band.
- **Saves:** additive catalog entry, so no save change. A saved Pumpkin loads and saves after the event (test 9). If the species is ever removed, the existing `unrecognizedPets` path keeps the raw entry.

## Odds display

The full per-species list is `AppController` page `"Odds"` (frozen). Its only opener is `ProgressionBrowser` "View roll odds →", which is on the old Upgrades card. `OpenPage("Upgrades")` now opens the research map, so in practice players see roll odds in the Luck cash-node tooltip in `ResearchBrowser`. I put the line there and exported the helper so the Odds page can show the same line in Epic color (request 2).

While the event runs, the per-podium chance of each normal species is really `0.98 x` its listed value, because the 2% replaces the normal draw. The line says "per podium", and the event line is disclosed next to the others. If you want it exact, request 2 has an optional scaled variant.

## Tests

Run in a fresh Run-mode server with the tests project synced:

```lua
require(game.ServerStorage.PetRollTests.EventChecks).Run()
require(game.ServerStorage.PetRollTests.FoundationChecks).Run()
require(game.ServerStorage.PetRollTests.PersistenceChecks).Run()
```

Each check patches `Config.Event` and restores every field afterwards, so the result never depends on the shipped values. All randomness uses fixed seeds, and the direct `MaybeReplace` checks use a fixed `now`.

1. The Pumpkin Chicken is weight 0, Epic, `limited`, appears in Order once, and copies Knight's stats, recruit/merge price and investment.
2. Inactive (disabled, before start, at/after end, and the shipped `0/0` window): 10,000 calls never replace, and the rng is not advanced (compared against a twin `Random`).
3. Disabled: 10,000 real `RollService:Roll` slots (8 podiums x 1,250 pulls) never offer it.
4. An ended window gives exactly the same seeded roll sequence (species and mutation) as a disabled event.
5. Active: about 2% of 50,000 seeded calls (within 15%), with exactly one rng draw per call.
6. Malformed config (chance 0, negative, >1, NaN, unknown species, string dates, `Enabled = "yes"`) stays inactive and draws nothing.
7. With `OfferChance = 1`: a fresh profile's starter roll stays the Duck, and a forced slot 1 (`debugNext`) keeps its species. Every other slot becomes Pumpkin at Knight's price with `chance == 0`. **This checks the foundation hook.** If it fails, the RollService guard is wrong, not EventService.
8. `odds.Pumpkin == 0` for every cash Luck level x pass x research bonus, and odds still sum to 1. `Rules.Draw` never returns it across 60,000 evenly spaced values.
9. A saved Pumpkin (level 2) loads with species, level, investment and Index discovery after the event ended, isn't treated as unknown, survives a second save, and earns the same as a Knight.

## Decor

`tools/map/MapDecor.luau` is a Studio command-bar script and isn't synced by Rojo.

- **Kit:** three new models in `ServerStorage.MapPropKit`. `Pumpkin1` (round), `Pumpkin2` (squat) and `PumpkinCarved1` (glowing Neon eyes, nose and grin on its -Z front, plus a shadowless warm `PointLight`). All are voxel style: a stepped orange body with stud texture on top, darker rib grooves, a green stem and leaf. They use no `kitRng`, so every existing prop is built exactly as before.
- **Scatter:** set `local HALLOWEEN = true` at the top and run the script.
  - It rebuilds normal `Decor` (deterministic, same result as before), then rebuilds `Workspace.MyChickenArmyMap.01_Environment.Decor_Halloween` with its own RNG (`SEED + 31`).
  - That gives 40 pumpkins, about 45% carved, in ones and twos. Half are just outside a home-plot or camp clearance box and half are just outside the road clearance.
  - Placement goes through the same `free()` check, so pumpkins stay clear of roads (16 studs plus radius), plots (22 pad), camps (14 pad), the King arena (inner 75), existing trees/rocks and the other props.
  - Carved faces turn toward the road or plot they border, with ±25° jitter.
  - The return string ends with `Halloween: N pumpkins (M carved) in Decor_Halloween.` Save the place afterwards.
- **After the event:** delete the `Decor_Halloween` folder. Running the script with `HALLOWEEN = false` leaves an existing `Decor_Halloween` untouched, so a normal decor rerun during the event keeps the pumpkins.

## Turning the event off

- Set `Config.Event.Enabled = false`, or just let `EndsAt` pass. `Active` is false from `EndsAt` onward, offers stop, and the odds lines disappear. The rng isn't touched, so rolls are exactly as without the event.
- Owned Pumpkin Chickens stay forever, and the Index keeps the card with "Limited (Halloween 2026)" (request 5).
- Delete `Decor_Halloween`.
- Leave the catalog entry in place. Removing it is save-safe through `unrecognizedPets`, but players' birds would disappear from their flock.
