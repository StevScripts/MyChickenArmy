# Handoff D1: 7-day login streak

**Branch:** `launch/d1-daily` (from foundation `bec87ac`). Contract: [`../13_D1_DAILY_STREAK.md`](../13_D1_DAILY_STREAK.md).
Not run in Studio. A `rojo build tests.project.json` packaged cleanly; no Luau run or type check was possible here.

## Files changed

- `src/server/DailyService.luau`: replaces the stub body.
  - `Rewards` table at the top (7 slots: minutes of income, free rolls). `MinIncome = 10`.
  - `Check(session, now, server)` skips the session if it isn't loaded, is closing or has `saveLost`, the same guard other transactions use. It uses `today = floor(now / 86400)`. `lastDay >= today` returns nil. A later saved day (another server's clock ahead) counts as already claimed, so the streak never resets because of clock skew.
  - If yesterday was claimed the streak goes up by 1, otherwise it restarts at 1. A broken streak of 2 or more records `daily.reset`. `best` keeps the maximum. The slot is `((streak-1) % 7) + 1`.
  - Cash = `floor(min(max(10, EarnedAmount(Income() * EggProductionMultiplier(), "eggs")) * minutes * 60, MaxCoins - coins))`, credited with `session:Credit(cash, "daily")`. `dailyGranted.cash` is the amount actually credited. Rolls go to `session.hillRollCredits` (HillService:Deliver turns them into recruits every 2 s while the flock has room). It never grants Galaxy Crate credits.
  - Sets `session.dailyGranted = {slot, streak, cash, rolls, day}`, then `Touch()`, `server.world:UpdateSession`, `daily.claim.<slot>` and the `daily.streak` histogram. Every server field is nil-guarded. It returns the grant table, or nil (useful for tests).
- `src/client/DailyRewardController.luau`: replaces the stub body. Keeps `new`, `Render`, `Destroy`.
  - Shows each `state.daily.granted.day` once per client. It waits while `app.offlineCash.gui ~= nil`, then 0.6 s more, and also while `app.intro:Pending()` (the first-visit film). It polls every 0.4 s, only while a grant is pending.
  - Built like the offline receipt: an inset container under `app.other`, a backdrop, a CanvasGroup panel, a gold header "Day N streak!" with a close button, and a dark body (ApplyPopupStyle).
  - Seven day tiles in one row that shrink with the panel: done days are green with a tick, today is gold with a white outline, future days are dimmed. Each tile shows "Day N", art (cash pile or the Luck icon) and "5 min cash" / "1 roll" / "60 min + 3 rolls".
  - Big reward text ("+$1.2M", "+1 free roll", or both on day 7), a short note, and one green "Collect" button. Collect, X, Escape and ButtonB close it and play the existing cash effect (`feedback:ShowCash`) or a Pop. They grant nothing.
  - Panel geometry: native Scale `0.92 x 0.6` with a 1.5 UIAspectRatioConstraint (height-led on wide screens, width-led on narrow ones). If Studio later authors `PetRollGui.MenuLayouts.DailyStreak`, `MenuLayout.Apply` uses that frame instead.
  - Today's tile pulses with one TweenService tween (repeat and reverse). Reduced motion disables the pulse and the entrance offset.
  - Studs use `Theme.Studs` (the sheet image) only. No new ScreenGui.
- `tests/DailyChecks.luau` (new): 9 checks, using fixed day numbers, isolated `PlayerSession.new` sessions and a stub server that records analytics names.
- `docs/team/launch/handoff/D1.md` (this note).

## Tests

Run in a fresh Run-mode server (tests project synced):

```lua
require(game.ServerStorage.PetRollTests.DailyChecks).Run()
require(game.ServerStorage.PetRollTests.FoundationChecks).Run()
```

DailyChecks covers:
1. The first check gives streak 1, slot 1 and $3,000 (the floor) for an empty flock, records analytics, shows in the snapshot, and is never saved.
2. A second check on the same day, or an earlier day, grants nothing.
3. The next day gives streak 2. A skipped day resets to 1 and records `daily.reset`; a broken streak of 1 does not.
4. Day 8 gives slot 1 again and `best` stays at 8 after a later reset.
5. Slot 3 gives +1 roll and no cash; slot 6 gives +2; slot 7 gives +3 rolls plus 60 minutes of cash; no crate credits. `HillService.Deliver` turns all 6 into recruits.
6. Cash is `floor(rate*300)` for a real flock, about 2x with 2x Cash, $3,000 at the floor, only the headroom near the cap, and 0 at the cap while the streak still advances.
7. Unloaded, closing and save-lost sessions are untouched.
8. A save round trip keeps the streak, a same-day rejoin doesn't re-grant, and the next day continues the streak.
9. The lead's stub server (`analytics=nil`) and a nil server are safe.

## Unsure / for the lead to decide

The popup waits for the intro film but appears at the start of the guide. The tutorial reserve still holds, but extra cash lets new players buy other upgrades sooner. If the owner prefers, defer the first claim until the guide finishes (that needs a rule change in the doc).

## Requests for lead

1. **2x Cash at login:** `GameServer:AddPlayer` calls `DailyService.Check` before `commerce:Load`, so on the login check `entitlements.DoubleCash` is not loaded yet and the reward ignores 2x Cash. Day changes while online already include it. Calling Check a second time later wouldn't help, because the first call already claims the day. To fix it, move the call into that `task.spawn`, right after `self.commerce:Load(player, session)` and before its `Send`, keeping the same `sessions[...] == session` and `not session.closing` guard. The grant then arrives in the second state packet, which the client handles. Or accept the gap.
2. Optional: in `AppController:OpenPage`, dismiss the daily popup like the offline receipt (`self.dailyReward:Dismiss(true)`), so a keyboard shortcut can't open a page underneath it. `Dismiss` is public.
3. Optional: author `StarterGui.PetRollGui.MenuLayouts.DailyStreak` in Studio to tune the popup's size and position natively.
