The old menus predominantly use proportional `Size`/`Position`, centered anchors, native list layouts, `TextScaled`, and `UIAspectRatioConstraint`. No `UIScale` was present in these five reference subtrees. Shop and Index each also contained two `UITextSizeConstraint` instances; those were not copied because the current request explicitly restricts sizing constraints to aspect ratios.

## Native layout review

- All geometry authored in the three modified modules uses scale components. No viewport breakpoints, per-device dimensions, offset rectangles, `UIScale`, or text-size constraints remain there. Hover/reveal effects tween ordinary `Size` and `Position` properties.
- Shop’s menu layout runs once after cards are created. Repeated rendering does not recalculate section geometry or compound sizes. Section aspect ratios depend only on the number of configured offers.
- Index’s grid lives in a width/aspect-constrained content Frame within its automatic-Y ScrollingFrame. Its aspect is `1 / (rows × 0.21 + (rows − 1) × 0.04)`. Grid row height and spacing therefore depend on content width, independently of the scroll canvas extent.
- Shop details use the same arrangement. The content height-to-width ratio is `0.18 + 0.12 + rows × 0.064 + (rows + 1) × 0.008`. Description, note, rows, and list padding divide by this ratio. Changing the number of disclosure rows extends the canvas without enlarging existing rows.
- Upgrades uses a plain Frame because all three cards fit its fixed native arrangement. There is no disabled or empty scrolling canvas.
- Purchase handlers, server quotes, catalog contents, saved discovery, disabled offers, and existing art remain in place.

Reviewed against Roblox’s official descriptions of [aspect constraints](https://create.roblox.com/docs/reference/engine/classes/UIAspectRatioConstraint), [grid sizing](https://create.roblox.com/docs/reference/engine/classes/UIGridLayout), and [automatic scrolling canvases](https://create.roblox.com/docs/reference/engine/classes/ScrollingFrame).
